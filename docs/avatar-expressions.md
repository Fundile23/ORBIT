# Avatar micro-expressions

ORBIT uses its earlier expressive planet/orb identity, with a dotted orbital ring and little moon. The creature redesign has been removed at the creator's request, but its enhanced facial range, distinct mood colours and bounded contextual reactions are retained. Brows, eyes, mouth, the orb and its surroundings can move independently without another animation dependency.

The top-of-chat avatar and shell face follow the current conversation; the welcome avatar has a neutral resting expression. The restored orb remains an animatable vector, not a static image.

## Decorative cues, not diagnosis

The avatar follows a tentative presentation cue generated by the same AI request that produces ORBIT's reply. It considers meaning and recent authorised conversation context, not a list of trigger words. The instruction covers indirect language, sarcasm, negation, mixed feelings and other languages; interpretation can still be wrong. The cue selects an appropriate companion response, not a diagnosis, verified mood reading, clinical classification or safety decision.

No extra model calls or stored mood labels are created. The model emits a bounded metadata line before its normal reply. The server validates an allowlisted tone and `clear`/`uncertain` certainty, strips that line before text is streamed or saved, and delivers a separate `{avatar: {tone, certainty}}` SSE record. Invalid, missing, truncated or uncertain metadata means neutral. No reasons, scores, metadata or mood profile are saved to the database or logged. The browser retains only the current turn's cue in memory. The legacy keyword heuristic remains as an isolated regression fixture, not an active chat decision path.

| Conversation cue | Expression / colour |
|---|---|
| Happiness or a small win | Joyful / sunshine yellow |
| Welcomed major good news or excitement | Excited / vibrant orange |
| Invited humour, boredom or banter | Playful / turquoise |
| Sadness, loneliness, explicit serious support | Supportive / soft rose pink |
| Anxiety or reassurance | Calm / fresh mint green |
| Frustration | Frustrated / crimson, composed rather than aggressive |
| Surprise without distress | Surprised / coral |
| Exhaustion | Tired / slate |
| Curiosity | Curious / electric violet |
| Explicit possible danger | Concerned / muted amber, never an alarm |
| Welcomed planning or serious discussion | Focused / deep blue |
| No clear cue or resting | Neutral / original soft blue |

Inference runs on submitted user turns, not unsent drafts or individual streaming tokens. Each new send starts neutral until the AI cue arrives. Short replies can follow context, while new topics should reset it. Reloading, cached-reply retries, route/account changes, failed requests and stopping a reply return to neutral; old cues are not reconstructed from history. Cues from an aborted/replaced request are ignored. The deterministic immediate-support path bypasses AI as before and emits a composed concerned expression. Avatar cues never select or change safety handling, consent, emergency guidance or persisted message content.

## Conversation lifecycle

Interaction state and tone are separate reusable selectors, not timer-driven emotional cycling:

- **Idle:** resting expression when no request is active and the composer is unfocused.
- **Listening:** attentive tilt when the text composer has focus. No microphone is used.
- **Thinking:** request is active but no reply text has arrived; a subtle moving orbit pattern.
- **Speaking / Replying:** text is actually streaming; slight mouth movement, not audio playback.
- **Facial range:** happy, excited, amused, empathetic/downcast, concerned, frustrated, curious, surprised and sleepy, plus relaxed, attentive, thoughtful and replying expressions. Serious cues never enable a playful effect.
- Completing, stopping or interrupting a reply exits thinking/speaking immediately.

The welcome avatar is 240px (196px on narrow screens). The chat header uses a 176px desktop / 136px mobile avatar, retaining message space and compact mobile controls. Small navigation/history avatars use the same orb identity without ongoing motion.

## Bounded contextual reactions

Only actual submitted turns create reaction events. A welcomed major milestone can trigger one short orb bounce and confetti; a smaller win gets sparkles. Playful context permits a restrained giggle movement, curiosity a tilt, surprise a brief startle, and distress a composed comforting movement. Reactions expire within 2.4 seconds. The same retry key does not replay, existing history/reloads do not trigger a celebration, and changes to a quiet tone suppress positive effects immediately. No reaction record is saved to the database.

The AI is instructed to distinguish happiness from excitement, concern from frustration, and surprise from curiosity. Fear, bad news or an explicit serious-support request should suppress celebration even when a wedding or another normally positive event is mentioned. Embarrassment alone is not an invitation to laugh. These are model instructions rather than guaranteed emotion recognition; malformed or uncertain cues use neutral.

Facial shape accompanies colour so the cue is not colour-only. Reduced-motion preferences retain static expressions/colours without ongoing movement; confetti and sparkles are hidden. SVG gradient IDs must be unique for every rendered avatar. Small history/navigation icons remain static; no new animation dependency is required.

Input and the existing UTF-8 SSE decoder preserve user and model emojis, including multi-code-point sequences. Enter does not submit during IME composition. The automated stream check splits a synthetic emoji reply at every byte boundary; it does not access account data.
